(v8.48 이후 매 버전 압축파일에 이 txt가 함께 들어갑니다)

■ 이 문서는 무엇인가
지금 이 압축파일 안의 project/ 폴더는 "개발용 소스"입니다.
여러 개의 .js 파일로 나뉘어 있어서, Claude가(또는 감사역님이 직접) 특정 부분만
찾아서 고치기 쉽게 만든 상태입니다.

실제로 내부망 PC에 옮겨서 여는 "결과물"은 이 여러 파일이 아니라, 아래 절차로
다시 합쳐서 나오는 HTML 파일 딱 1개입니다. 지금까지 쓰시던
"IT감사_라이프사이클_플랫폼_v8_XX_2026XXXX.html" 같은 파일과 완전히 동일한 형태입니다.


■ 준비물
- Node.js (버전 18 이상 권장). https://nodejs.org 에서 "LTS" 버전 받아서 설치.
  (사내 PC에 인터넷이 막혀 있다면, 인터넷 되는 PC에서 설치 파일을 받아 옮기거나
   IT부서에 Node.js 설치를 요청하시면 됩니다. 한 번만 설치하면 계속 씁니다.)
- 압축을 풀 폴더 (예: C:\work\it-audit-platform\ 또는 원하는 위치)


■ 처음 한 번만 하는 작업

1. 압축파일을 원하는 위치에 풀어놓습니다.
   예: C:\work\it-audit-platform\project\

2. 명령 프롬프트(cmd) 또는 PowerShell을 열고, project 폴더로 이동합니다.
   > cd C:\work\it-audit-platform\project

3. 아래 명령을 한 번 실행합니다. (필요한 빌드 도구를 내려받는 과정, 1~2분 소요)
   > npm install

   이 명령을 실행하면 project 폴더 안에 node_modules 라는 폴더가 새로 생깁니다.
   이건 빌드 도구들이 들어있는 폴더라 용량이 꽤 크지만(수십MB), 신경 쓰지 않으셔도
   됩니다. 이후 소스를 다른 사람에게 전달할 때는 이 node_modules 폴더는
   빼고 보내시면 됩니다(받는 사람이 자기 PC에서 다시 npm install 하면 됩니다).


■ 수정할 때마다 하는 작업 (핵심)

1. project/src/ 안의 원하는 파일을 엽니다.
   - 인터뷰 스크립트를 고치고 싶다
     → project/src/data/interview-scripts.js
   - AI 순서도·분기형 기본값을 고치고 싶다
     → project/src/data/ai-flow-defaults.js
   - 도메인(감사영역) 정의나 체크리스트 항목을 고치고 싶다
     → project/src/data/domains-data.js
   - 화면 동작(버튼 눌렀을 때 로직 등)을 고치고 싶다
     → project/src/app.js
   - 화면 레이아웃/디자인(CSS)을 고치고 싶다
     → project/index.html

2. 수정을 마쳤으면, project 폴더에서 아래 명령을 실행합니다.
   > npm run build

   실행이 끝나면 project/dist/index.html 파일 1개가 새로 만들어집니다(또는 덮어써집니다).
   이게 바로 "지금까지 쓰시던 단일 HTML 파일"입니다.

3. 그 파일을 원하는 이름으로 바꿔서 저장합니다.
   예: dist/index.html
       → IT감사_라이프사이클_플랫폼_v8_49_20260910.html

   (지금까지 쓰시던 버전 관리 프로토콜 그대로 적용하시면 됩니다:
    ① app.js 안의 SYSTEM_VERSION/SYSTEM_BUILD_DATE 값 갱신
    ② 파일명에 버전·날짜 반영
    ③ "사용법 가이드" 탭 변경 이력 표에 새 버전 행 추가)

4. 이 파일을 내부망 PC로 옮겨서 여시면 됩니다. 지금까지와 완전히 동일하게
   인터넷 연결 없이도 실행되고, 폴더 하나 복사하듯 그대로 이메일 첨부·USB
   복사해서 옮기실 수 있습니다.


■ 자주 묻는 질문

Q. npm run build 할 때마다 매번 npm install도 다시 해야 하나요?
A. 아니요. npm install은 "처음 한 번만"(또는 package.json이 바뀌었을 때만) 하면
   됩니다. 그 다음부터는 코드를 고칠 때마다 npm run build만 실행하시면 됩니다.

Q. 결과 파일이 원본이랑 완전히 똑같이 생겼나요?
A. 네. 여러 파일로 나뉜 것은 "만드는 과정(소스)"일 뿐이고, npm run build를
   거치면 CSS·JS가 전부 그 파일 안에 다시 합쳐진 진짜 단일 HTML 파일 1개가
   나옵니다. 빌드 도구(Vite + vite-plugin-singlefile)가 이 합치는 작업을
   자동으로 해줍니다.

Q. 화면에서 실시간으로 미리 보면서 고칠 수는 없나요?
A. 가능합니다. project 폴더에서 `npm run dev`를 실행하면 브라우저에서
   http://localhost:5173 주소로 접속해 미리보기를 볼 수 있고, 코드를 저장할
   때마다 화면이 자동으로 새로고침됩니다(핫리로드). 다만 이 상태의 화면을
   그대로 배포하면 안 되고, 배포용 파일은 항상 npm run build로 뽑은
   dist/index.html을 쓰셔야 합니다.

Q. node_modules나 dist 폴더도 압축해서 다음 세션(Claude)에 전달해야 하나요?
A. 아니요. node_modules(빌드 도구)와 dist(빌드 결과물)는 매번 새로 만들 수 있는
   것들이라 압축·전달 대상에서 빼는 게 일반적입니다(용량도 크고요). src/,
   index.html, package.json, vite.config.js 이 정도만 있으면 충분합니다.

Q. 오류가 나면 어떻게 하나요?
A. "npm run build" 실행 중 빨간 글씨로 에러가 뜨면, 그 에러 메시지를 그대로
   복사해서 다음 Claude 세션에 붙여넣어 주시면 원인을 확인해 드릴 수 있습니다.
   대부분 특정 파일의 문법 오류(괄호 안 맞음 등)이므로, 에러 메시지에 파일명과
   줄 번호가 함께 나옵니다.


■ 참고: 이 구조를 처음 만든 배경
기존에는 31,000줄짜리 HTML 파일 하나를 통째로 열어서 작업했는데, 이 방식은
① Claude가 매번 파일 전체를 읽어야 해서 토큰(사용량)이 낭비되고,
② 사람이 특정 부분을 찾기도 어렵다는 문제가 있었습니다.
그래서 "개발 중에는 여러 파일로 나누고, 배포할 때만 다시 합친다"는 구조
(Vite + vite-plugin-singlefile)로 전환했습니다. 데이터(인터뷰 스크립트 등)는
이미 분리가 끝났고, 화면 로직(app.js, 아직 하나로 뭉쳐 있음)은 이후 단계에서
탭 단위(설문 빌더/인터뷰 가이드/증빙관리/배포 등)로 추가 분리할 예정입니다.
